# Cuemark — working notes

Last reviewed 2026-08-11. Items fixed or already-resolved as of this review were removed
rather than kept here — the commit log (`waveform-scrub-vinyl-jog` branch) and CLAUDE.md
already carry the full "why" for each. What follows is only what's still actionable.

## Needs live-hardware verification (fixed in code, unconfirmed on real gear)

- **Headphone cue routing lost on track load.** Fixed in `src/App.svelte`
  (`ensureAudioLoaded` now re-applies `deck.cueEnabled` to the freshly rebuilt pipeline, the
  same way gain/rate/volume already were). Verify: enable cue on a deck, load a new track
  onto it, confirm cue audio survives without re-toggling the button.
- **Waveform snapping to the track start** during a drag on a *playing* WebCodecs-path deck,
  and a **hot cue appearing to jump to the start** instead of its stored position (same root
  cause). Fixed in `src/lib/renderer/seekBus.ts` — `getDeckTime()` now falls back to
  `pendingSeekTarget` instead of `null` right after a seek. Verify both: drag a playing deck's
  waveform and watch for the flash-to-0; press a hot cue on a *paused* deck (where the position
  poll never runs at all) and confirm it lands on the stored time, not 0.
- **Jog wheel variable-speed pitch bend.** Implemented in `src/lib/midi/handler.ts`
  (`JOG_BEND_PER_TICK_PER_SEC` / `JOG_BEND_MAX`) — bend now scales with wheel speed instead of
  a fixed ±0.02 step per tick. The constants are estimates extrapolated from the *paused-deck*
  vinyl calibration, not measured on this branch — retune by ear on the Starlight, same
  procedure as `SCRATCH_MODE_PARAMS` (`docs/design/waveform-scrub.md`).

## Open bugs

### Jog wheel reverse doesn't play video in reverse [confirmed still open]
Real gap, not a quick patch. `codecPlayer.ts`'s frame ring only covers ~0.7–1.28s of reverse
travel; beyond that `getFrameForTime()` freezes on the oldest cached frame instead of
continuing to scrub backward. This is exactly the unbuilt "tier 2" (keyframe-quantized reverse
seek) already called out in `docs/design/codec-frame-cache.md` — treat it as a real feature to
scope, not a bugfix.

### Clipping/popping on "Jonas Rathsman - Tobago" [downgraded — mechanism likely already closed]
The suspected cause (two `pulsesink`s sharing one PipeWire node — `audio-dropout-mid-playback.md`
H1) is structurally removed by the 2026-08-11 shared-output default flip, but was never actually
confirmed as *the* cause of this symptom — no reliable reproducer was ever obtained to test H1
against, on either topology. No tool in the repo analyzes a source file for pre-existing
clipping (only destination capture exists — `scripts/scratch-capture.sh` / `scratch-envelope.py`).
Fastest next step, and it needs no cuemark code: run `ffmpeg -af astats -f null -` directly on
the source file to settle whether the popping is baked into the file before spending more
engineering time on it.

### OVR waveform stutter [mostly explained — one thread still open]
Dragging a **paused** deck in OVR mode is *supposed* to sound choppy — `waveform-scrub.md`
already documents the overview's coarse pixel-to-time scale (~24x coarser than the zoomed view)
legitimately saturating the scratch servo's snap threshold, and snapping is deliberately silent.
Don't touch `SCRATCH_TARGET_SNAP_SECS` or `secondsPerPixel()` over this — it's working as
designed. What's still genuinely untested: dragging a **playing** deck in OVR goes through a
different, throttled silent-seek path (`seekBus.ts`, `SILENT_SCRUB_SEEK_MS`) that the design
doc itself flags as never live-verified — that's the more likely source of a real stutter.
Next step: a `scratch-capture.sh` run against that specific scenario before touching anything.

## Feature requests — prioritized

Ranked by rough value/effort; each "scope" note is a starting point for whoever picks it up,
not a committed design.

1. **[HIGH] LEGACY/CODEC deck indicator rework.** Replace the current "CODEC" badge with a
   "LEGACY" badge shown only when a deck is *not* on the WebCodecs path — never for audio-only
   files, which already work fine either way. Scope: find the badge in `DeckCard.svelte`; this
   also closes a known bug already on record (`todo.md`) where the CODEC badge doesn't clear
   when a deck falls back to legacy. Small, isolated UI change.
2. **[HIGH] Show video resolution in the deck UI.** Pairs with #1 (same row, same purpose):
   surface `coded_width`/`coded_height` (WebCodecs path) or `videoWidth`/`videoHeight` (legacy
   `<video>`), since 4K playback is measurably expensive on this machine (54–77ms/frame vs.
   roughly 1/16th that for 720p, per `todo.md`) and resolution is currently invisible in the UI.
   Small.
3. **[MEDIUM] Auto DJ toggle.** Replace the "Rnd"/"Next" buttons (reportedly unused in
   practice) with a single "Auto" toggle. This is really the existing unbuilt "Auto-advance
   option" from `todo.md`'s play-queue section (auto-load `GET /queue/next` when a deck's clip
   ends) exposed as a toggle instead of two buttons nobody uses. Scope: UI swap plus wiring
   actual auto-advance logic — medium.
4. **[MEDIUM] Quantize beat markers to detected kick onsets.** Addresses SET BEAT drifting over
   the length of a long track. `bpm.ts`'s comb/Fourier fit already does onset detection
   internally for the initial grid fit; `todo.md` Step 4 already flags "snap SET BEAT to the
   nearest detected onset" as an unbuilt optional — this request is that feature. Scope: retain
   the onset list from analysis (currently discarded after the initial fit) and add a re-snap
   action. Medium.
5. **[LOW] Resizable/wider Digger Queue column.** UI-only, `DiggerQueue.svelte`. Small.
6. **[LOW] Default gain synced from Digger.** Store a per-track default gain in Digger, apply
   it on load (reset to default unless Digger supplies one), mirroring the existing
   bpm/downbeat pull-on-load pattern. Cross-repo: needs a Digger schema field +
   `GET /tracks/{id}/cuemark` addition, plus applying it in cuemark's load path. Medium, two
   repos.
7. **[LOW] Auto-save session history to Digger as "Sessions"**, with transition points
   recorded for future auto-DJ training. `history.ts` already tracks this locally; needs a new
   Digger endpoint (e.g. `POST /sessions`) plus a push call analogous to the existing
   `pushMarker` fire-and-forget pattern. Medium-large, two repos — and probably wants #3 done
   first, since "transition points" only means something once auto-advance exists.
8. **Codebase review/refactor for maintainability.** Real concern, but not a scoped task as
   written — needs its own short audit (likely candidates: `App.svelte`'s size, the audio
   pipeline's accumulated complexity reflected in how much of CLAUDE.md it now occupies)
   before it's actionable. Flagging rather than scoping blind.

## Digger feature requests — prioritized

Different repo/codebase (`~/repos/digger`), captured here alongside the cuemark notes above.
Digger's own `todo.md` is chronological/log-style rather than prioritized; these aren't merged
into it.

1. **[HIGH] Auto re-encode 4K sources to a 1080p proxy**, kept alongside the original (same
   pattern as cached cover art), with cuemark preferring the proxy when present. Directly
   motivated by the 4K cost measured above (#2) — worth confirming whether 1080p or 720p is
   the right target given those numbers. Cross-repo: Digger generates/serves the proxy,
   cuemark prefers it at load.
2. **[MEDIUM] WaveformDetail: same drag/scrub/jog UX as cuemark**, for interface consistency —
   worth doing once cuemark's own vinyl-jog UX (this branch) is stable enough to be worth
   porting.
3. **[MEDIUM] TrackDetails lyric column** — wider/resizable, fixed to the window height and
   scrollable, with the current line kept centered so lyric auto-scroll doesn't yank the
   user's view away from the main page.
4. **[LOW] Artist view parity pass** — pause without losing position, add to queue, single-track
   download, custom track ordering. Bundle of small UI additions matching what the Playlist and
   Track Detail pages already got.
5. **[LOW] Save queue as playlist/crate; clear queue.**
6. **[LOW] Cache cover-art metadata in the DB** for all tracks (same pattern already used for
   videos).
7. **[LOW] Enrich profile: scrape an artist bio from the web** instead of generating one from
   tracks/playlists.
8. **Plex as a media source** (movies too) — largest item here, a new integration; not scoped
   further.
