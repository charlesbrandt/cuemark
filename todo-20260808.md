around for future machines that can handle it. This machine does not: measured 2026-08-09,
presenting a single 3840x2026 frame costs 54-77ms of main thread in cuemark's preview draw
(`[aux-loop] preview/deck-0 … dur max=77.0 | busy 14%`), which is ~16x the pixel cost of a
720p file and is a plausible source of audio starvation during scratch gestures. Wants:
 - a derived/proxy file alongside the original rather than replacing it (same pattern as
   cover art / cached media), so the choice is reversible per machine
 - cuemark should prefer the proxy when present; the original stays the archival copy
 - worth measuring whether 1080p is the right target or 720p, given the numbers above
